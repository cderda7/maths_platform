Carson, 2026-09-16: "change a first submission & a score (just for one of them, say coral — keep amber)." Coral (Priya,

## The question and the reused slip

Every question in coral's union after individual review already had an explainer (Priya, right first time on
everything) except Q10, which is already moved to class review by ticket 337 and named out of bounds by this ticket's
own brief. Every other question (Q4, Q5, Q8, Q9) needed the same three members' first submissions changed (Priya,
Amelia and Aiden all had them right; only Tomas ever needed them). Q8 was the cheapest of those four to build
honestly: its evaluation table (`data/evaluation.ts`) carries exactly one recognised wrong line, `Q8_MIRROR` ("x = -1
or x = -3", misconception `graph-signs`, "read the graph's intercepts with the signs flipped"), already defined in
`data/slips.ts` but used by no classmate before this ticket ("nobody slips on Q8" was the class's shape until now).
Reusing it three times, for the three coral members who needed a new mistake, is real: it is the class's own
recognised slip on this problem, not an invented one, matching "diagnostic distractors from real slips" the same way
ticket 332's "slipped again" rewrites do.

**Priya, Amelia and Aiden each get Q8 wrong on their first submission** (a new `wrong: ["q8"]` entry, `attempts.q8:
Q8_MIRROR`), each with a teacher note and a first-person clarification. **Each one's individual-review rework slips
again**, the same line, the way Jordan's, Zara's, Isla's, Lucas's, Oliver's and Ruby's Q7 reworks already do (ticket
332's precedent): `SET6_REVIEW.second` gains `priya.q8`, `amelia.q8` and `aiden.q8`, all `Q8_MIRROR`. `canExplain`
(`lib/reviewUnion.ts`) reads this exactly as it reads every other one-off-that-slipped-again: `fixedInIndividualReview`
is false, so none of the three can explain it, and — since Tomas already brought Q8 (never attempted, `done: 7`) —
**nobody present at coral can explain Q8** once individual review is over. No code changed to make this true: the
group rule, the board simulation and every screen that reads `canExplain`/`stillToReview` already do the right thing
once the data says so.

**The group's own working** (`SET6_REVIEW.groups.coral.q8`, and `SIMULATED_BOARDS.coral.q8`'s last try) cannot be
`Q8_MIRROR` unchanged: `data/story.test.ts`'s `reviewMismatches` refuses a group version that is byte-for-byte a
member's own first submission (`recordReview.ts`'s rule: "the group's own freshly written working ... never a
member's first submission"). Q8 has no second recognised wrong line to build a different-looking attempt from (unlike
Q7's three distinct wrong turns, or Q9's multi-line working), so **`CORAL_Q8_LAST`** is the one mirrored line written
twice — two separate turns at the board both flipping the same signs, still real, still shared, just not identical in
shape to any one member's own one-line submission. `SIMULATED_BOARDS.coral.q8` is `[SLIPS.q8, SLIPS.q8, SLIPS.q8,
CORAL_Q8_LAST]`: the rule's own four-try "nobody can explain it" shape (`triesFitRule`/`ruleTries` in
`lib/groupSim.ts`), which the code already produces unprompted once `explainableAt` reads false — this array only
needed to exist so the *group's report tile* and the *simulated board's last try* show the same thing
(`data/story.test.ts` holds them equal), the way every other group's authored board already does.

## What follows automatically, and what needed a hand

Everything downstream of `data/classmates.ts` and `data/classmates-review.ts` is derived, not stored twice, so most of
the ticket is those two files plus the two narrow additions above:

- **Set scores** (`lib/setScore.ts` `recordScore`, first submission only): Priya's, Amelia's and Aiden's drop by
  one each. Nobody else's first submission changed, so no other score moved.
- **Coral's board**: Q4, Q5, Q7, Q9, Q10 unaffected (still solved by an explainer at the table); Q8 takes three
  wrong checks, is left for now, and closes unsolved on its return, same shape as mint's and violet's Q7

- **The Mistakes tab's per-question counts and rows** (`lib/mistakes.ts`): Q8 gains a row (Priya, Amelia, Aiden), the
  class-wide "right" count for Q8 drops by three.
- **Class review's picks** (`data/classmates-review.ts` `SET6_CLASS_REVIEW_PICKS`, `data/story.ts`
  `STORY_CLASS_REVIEW`): Q8 joins Q7 and Q10 as a question at least one group left unsolved, so
  `recordReview.ts`'s own rule (class review covers *every* such question) requires it; two of coral's three matching
  first submissions (Priya, Amelia) go on the board, unnamed, the same shape as the others. This does **not** collide
  with ticket 337's split-review suggestion: Q8's class-wide "correct after corrections" count falls from 13 to 10,
  still short of the below-half line (10 × 2 = 20 ≥ 19) that would make it eligible to be pre-ticked there — checked
  by hand and by `lib/splitReview.test.ts`'s existing "one question below half and none" case, which now reads Q8's
  10 where it used to read 13.
- **The class story sheet** (`data/story.ts` `STORY_REVIEW`, `STORY` cells, `STORY_CLASS_REVIEW`): Priya's, Amelia's
  and Aiden's Set 6 review cases gain a `kept` (still-wrong) Q8 entry; Tomas's Q8 case changes from `grp` (the group's
  rework holds) to `kept`; Priya's, Amelia's and Aiden's Set 6 graphing cell drops from `secure` to `solid` (one slip
  among many held graphing lines — still a 1-in-5-or-more ratio, so `lib/hierarchy.ts`'s rule reads it as solid, not a
  gap), each with a pattern naming the misconception. `specs/class-story.md` is regenerated (`npm run story:sheet`).
- **The one blanket rule this breaks:** "Priya is secure in every category on every set" — the reason coral could not
  have an unsolvable question in the first place (`architecture/332.md`: "Priya had all ten right"). It is now true
  everywhere except Set 6's graphing, and every place that stated the old blanket rule (a rendered rule line in
  `lib/classStory.ts`, `README.md`, and several tests keying off "Priya has nothing to fix") is updated to the
  narrower, still-true statement. This is the one deliberate, foreseen breakage the ticket exists to make.
- **The diagnostic** (`data/diagnostic.ts`): Q8's "mirrored in the y-axis" distractor gains `slip: Q8_MIRROR` (a local
  constant, matching the file's existing pattern of one local string per recognised slip), so it is picked
  automatically by whichever of the three classmates it belongs to instead of needing a manual `picks` entry; Tomas
  (who never reaches Q8) is dropped from `picks.a` since that bucket is for options with **no** real slip evidence,
  which Q8's "a" no longer lacks.
- **The simulated race** (`data/group-scripts.ts` `SIMULATED_PACE`): unchanged. Coral's finish time moves later on its
  own, purely as a consequence of Q8 costing three wrong checks, the pause and a return try instead of one clean

## Judgment calls

- **Which question.** The ticket names avoiding Q7 and Q10 (already handled by ticket 337's split). Of the four
  remaining candidates in coral's union (Q4, Q5, Q8, Q9), all need the same three first submissions changed (Priya
  unconditionally, since she is otherwise right on everything; Amelia and Aiden, since only Tomas ever needed these
  four). Q9 was ruled out separately: giving Priya, Amelia and Aiden a Q9 mistake drops the class-wide Q9 tally from
  10/19 to 7/19, crossing ticket 337's below-half line and pre-ticking Q9 for the class-review split — a real
  collision, checked by running the actual `talliesAfterCorrections` before picking. Q4, Q5 and Q8 all cost the same
  three flips; Q8 was chosen because it has exactly one recognised wrong line already sitting unused in the
  evaluation table and no other narrative attached to it, so reusing it needed nothing invented and touched no other
  student's existing story. **Screen: none directly (a data/engineering choice); the closest surfaced effect is the
  Mistakes tab and the class story sheet, both read by the teacher.**
- **Three first submissions, not one.** The ticket's problem statement hopes for "ideally exactly one." Mathematically
  it cannot be one while keeping Q7 and Q10 off the table: Priya is the class's only always-right student, so she
  alone would leave two other present members (Amelia, Aiden) still able to explain any of Q4/Q5/Q8/Q9. The
  acceptance criteria anticipate this ("the changed students'" set scores, plural), so three flipped first submissions,
  chosen as the true minimum given the Q7/Q10 exclusion, is the answer. **Screen: the teacher's Class View Set column
  (three students' numbers move) and each of their own reports.**
- **The group's "last try" is the one slip written twice, not a distinct escalating sequence.** Every other unsolved
  question (Q7, Q9, Q10) has more than one recognised wrong line to draw from, so its board's last try looks like a
  real multi-turn disagreement. Q8's evaluation table has exactly one. Repeating it was chosen over inventing an
  unrecognised second line (which the evaluator would read as "unclear", explicitly checked against) or reusing a
  member's own submission unchanged (explicitly checked against and refused). **Screen: the teacher's Mistakes tab,
  "Where groups went wrong" card for Q8, and class review's board (Priya's and Amelia's identical-looking working
  shown as two separate examples).**
- **Coral's race position moves from "before the demo group's board" to "just after it," rather than being retuned
  back to its old slot.** The extra ~72 seconds Q8's ladder costs (three wrong checks, the left-for-now pause, a
  failed return) is the same mechanic that already makes mint and violet finish later than sky; retuning coral's pace
  purely to preserve its old finishing slot would have hidden a real, honest consequence of giving it a genuinely
  unsolvable question. Amber's and mint's and violet's paces are untouched. **Screen: the teacher's group progress
  card and the race/leaderboard during group review — coral no longer visibly "wins" alongside amber.**
- **The unit test for "a group with nothing left to review sits out" (`lib/groupSim.test.ts`) could no longer use
  coral (Priya + Aiden alone), since neither is clean any more — no classmate on Set 6 has zero needs after this
  ticket.** Rewritten to check the now-true opposite (coral no longer sits out there; it works Q8 alone instead,
  nobody at the table to explain it). The describe block's other two cases (Sam's own group, unaffected) still cover
  the sit-out mechanism itself. **Screen: none (test-only); the sitting-out mechanic is still exercised live by any
  group whose present members are all already fixed, which no longer includes coral or Priya alone.**
